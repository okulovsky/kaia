# Проверка миграции на хост

Дата: 2026-11-08. Исполнение обработки перенесено в generation/local; удалены код и экспорт WakewordData, зависимость от Piper/sample generator. Framework BrainBox не изменён. Старые Docker-образы и пользовательские ресурсы сохранены.

## Подтверждено

- 39 тестов прошли без пропусков в тестовом окружении Windows/Python 3.12. Проверены локальные ресурсы и ACAV, нормализация, mmap, словарная генерация негативов, явный checkpoint для неизвестных слов без скрытого скачивания, бюджет и восстановление, отдельные стабильные Parler-задания для негативов, отбраковка и неизменность готовых исходников.
- Настоящие augment_clips и ONNX-модели на Windows/CPU: четыре массива (2,16,96), NATIVE_HOST_FEATURES_OK. Модели передаются явными путями из cache; запись в site-packages не требуется.
- Измерение небольшого native smoke: 44,28 с, пик суммарного RSS процесса и его дочерних процессов около 464,7 МиБ. Измерение выполнялось параллельно удалённому тесту и не является прогнозом для полного датасета. Данные: host-native-measurement.json и host-native-validation.json.
- Локальный runtime закреплён в requirements-host.lock.txt (100 пакетов, CPU PyTorch). Установка проверена в отдельном тестовом окружении; зависимости существующего окружения пользователя автоматически не менялись.
- Через настоящий API BrainBox подтверждены образы, сервисы и модели ParlerTTS mini-v1 / Vosk en. make check показывает готовые удалённые компоненты и отсутствие полного локального cache.
- На диске D недостаточно места для общих корпусов. Добавлена оценка места до setup; загрузки больших корпусов при этой проверке не выполнялись.

## Сквозная проверка

Запущен тест через настоящий BrainBox с одной записью на class/split, настоящими ONNX-моделями и небольшими синтетическими фоновыми/RIR/ACAV-ресурсами. Это проверка связности, а не качества корпуса. Состояние и лог сохранены в .staging/real-host-fixture/run-001 и .staging/real-host-run.log. Первый позитив прошёл синтез, Vosk и crop. Итог: complete; подробности приведены ниже.

## Ограничения и оставшаяся приёмка

- Полные examples/minimal.json и full.json на FMA/MIT/ACAV не выполнены из-за свободного места; для них нужно перенести resource_folder на диск с достаточной ёмкостью.
- Python 3.11 объявлен поддерживаемым kaia, но локальная обработка проверена только на 3.12.
- Не проведено сравнение качества с исходным Piper на независимом реальном аудио. Переход на Parler намеренно изменяет распределение негативов.
- Негативы сохраняются целиком, без нового Vosk-фильтра и crop. Это сохраняет существующую политику обработки негативов; качество произношения требует проверки реальными записями.
- Нужна независимая проверка документации другим разработчиком. Старые проверки предыдущей архитектуры в validation.md являются историческими.


## Итог сквозного прогона и повтор

Сквозной прогон завершился успешно: четыре массива (1,16,96), по одной принятой записи в каждой class/split, 0 review. В API проверены все шесть заданий: четыре ParlerTTS и два Vosk, все finished без ошибок. Время от первого этапа до завершения около 1019 с, включая запуск контейнеров/загрузку моделей. Повтор той же команды завершился из кэша без этапов синтеза. Доказательства: host-real-validation.json. Это не заменяет examples/minimal.json/full.json на полных корпусах.

Итоговый набор модульных/контрактных тестов: 39 тестов, все успешны, без пропусков. После изменения сравнения локальных ресурсов дополнительно повторены 8 тестов пайплайна; после изменений загрузчика — 6 тестов локальной обработки.

## Источник DeepPhonemizer

Исходная S3-ссылка возвращает 403. Используется опубликованная NRC-CNRC копия ARPABET checkpoint en_us_cmudict_forward.pt: https://huggingface.co/NRC-CNRC/en_us_cmudict_ipa_forward_g2p/tree/524f09e81b3962ffa5b3ef5af9953bbc059cce99 . Ревизия и SHA-256 c5db2e1b13575c822b13579482b2a623454f5d769b9257d28e91eedc9688bdeb закреплены в defaults и примерах. Это именно ARPABET-файл, несмотря на IPA в имени репозитория.

В checkpoint имена классов токенизатора используют namespace deep_phonemizer. На setup адаптер отображает три класса в dp.preprocessing.text, сохраняет совместимый checkpoint и проверяет загрузку. Все 79 тензоров побитно совпадают с полученным файлом; замена весов и смешивание голосов не выполняются. Криптографическое сравнение с недоступным исходным S3-файлом невозможно, поэтому не заявляется.

Настоящий локальный fallback проверен на неизвестном слове computeroo: получены ARPABET-фонемы и негатив interpretation без скачивания в run. Результат — host-oov-validation.json. В старом позиционном буфере checkpoint есть нечисловые элементы начиная с позиции 4085; конвертация их не меняет, проверка охватывает короткое слово, а не произвольные многотысячные последовательности.
