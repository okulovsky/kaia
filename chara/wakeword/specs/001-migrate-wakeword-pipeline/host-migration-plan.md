# План миграции WakewordData на хост

Статус: архитектура согласована пользователем 2026-11-08; перенос кода реализован и проверен. Результаты: host-validation.md. Этот план заменяет прежние решения о Piper и выполнении обработки через WakewordData. Старые отметки tasks.md относятся к предыдущей архитектуре.

## Целевая архитектура

Chara выполняет подготовку ресурсов, generate_adversarial_texts, нормализацию, акустическую аугментацию и извлечение ONNX-признаков на хосте. BrainBox предоставляет только ParlerTTS mini-v1 для позитивного и негативного аудио и Vosk en для распознавания. Piper, смешивание голосов, checkpoint Piper и sample generator исключаются. Framework BrainBox не изменяется.

DeepPhonemizer для неизвестных слов остаётся частью локальной генерации негативных текстов: это согласованное следствие переноса всей логики WakewordData на хост. Его checkpoint подготавливается явно в setup, фиксируется в манифесте и не скачивается скрыто во время run. ONNX-модели признаков также работают локально. Прежняя формулировка «все модели через decider» заменена этим разделением; синтез и распознавание остаются удалёнными.

В generation/ остаются предметные модули пайплайна. Локальные операции группируются в generation/processing/ либо generation/local/ после проверки конфликтов имён. Корень wakeword сохраняет публичный API, scripts — точки входа. Код хоста не импортирует app-модули удаляемого decider.

## Политика негативов при реализации

Сохранена существующая обработка негативов целиком. Изменён только TTS-backend: Parler вместо Piper. Новые контекст, Vosk-фильтрация и crop негативов не вводились. Позитивы сохраняют короткий контекст и Vosk-crop.

Реальный прогон на небольших тестовых ресурсах и повтор из кэша выполнены. Полные корпуса, проверка качества на реальных записях, Python 3.11 и независимая проверка инструкции остаются отдельными проверками.
