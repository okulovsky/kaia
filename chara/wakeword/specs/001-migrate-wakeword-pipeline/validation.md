# Проверка реализации

Дата: 2026-11-04. Реализованы 33 из 36 задач. T027, T035 и T036 остаются открытыми.

## Автоматические проверки

Из корня kaia:

```powershell
& .venv/Scripts/python.exe -m unittest discover -s chara/wakeword/tests -v
```

Результат: 25 тестов, все успешны, пропусков нет. Проверены порог confidence, поиск слова и границы crop; сохранение review; лимит 3N и восстановление счётчиков; неизвестный статус отправки; повтор Vosk без нового TTS; замена после поздней отбраковки; повтор обработки после технических ошибок; остановка при общей ошибке; несовпадение настроек и повреждённые выходы. Сквозная оркестрация проверена с FakeBrainBox, а не с настоящим синтезом.

## Настоящий ML worker в Docker

Контейнер chara-wakeword-worker-check, Python 3.11.11, CPU, объединённый requirements.lock.txt (189 пакетов). Успешные контрольные отметки: WORKER_HTTP_OK, NATIVE_FEATURES_OK, FINAL_ENVIRONMENT_OK, RESOURCE_PREPARATION_OK. Итоговый код контейнера: 0.

Проверены HTTP marshalling и нормализация stereo 8 кГц в mono 16 кГц, настоящие augment_clips и ONNX embedding/melspectrogram. Получены четыре непустых конечных массива формы (2, 16, 96). Версии и результаты сохранены в worker-environment.json и native-validation.json. Успешно импортированы закреплённый Piper sample generator и datasets.

Подготовка ресурсов проверена на локальных WAV/NPY: контрольные суммы, повторное чтение кэша, отклонение повреждённого ресурса, выделение 10% train и следующего 1% validation из ACAV. Ответ HTTP 200 на Range-запрос корректно перезапускает загрузку вместо дописывания файла. Это проверка механизма; полные ACAV/FMA/MIT и TTS-модели в этом прогоне не загружались.

Проверка выявила неоднозначность importlib.metadata при нескольких установленных метаданных пакета: снимок версий теперь использует тот же механизм выбора, что и последующая проверка. Повторный прогон успешен.
